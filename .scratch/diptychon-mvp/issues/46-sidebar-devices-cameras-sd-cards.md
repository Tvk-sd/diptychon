## Summary

When a camera or SD card is connected, it does not appear anywhere in the app.
There is no way to navigate to it from the sidebar, so photos on a card can't be
browsed or copied off without going through Finder first.

## Steps to reproduce

1. Launch Diptychon.
2. Plug in an SD card (or connect a camera / card reader) — confirm it mounts and
   is visible in Finder under **Locations**.
3. Look at Diptychon's left sidebar.

**Expected:** the SD card / camera shows up as a navigable item (like Finder's
Locations / Devices), clicking it opens the card's contents in the active panel.

**Actual:** nothing appears. The sidebar only shows **Places** (Home, Desktop,
Documents, Downloads, Applications) and **Pinned**. The card is reachable only by
typing its `/Volumes/...` path into Go to Folder (issue 15).

## Root cause (confirmed)

Not a regression — the surface was never built. `SidebarView` renders exactly two
sections, `Places` (a fixed system-folder set) and `Pinned`
(`Sources/Diptychon/Panel/SidebarView.swift:51`, `:56`). There is no Devices /
Locations section and nothing observes mounted volumes. Issue 16 explicitly
deferred this ("Recents, Tags, iCloud/Locations — add as new sections once the
frame exists").

## Proposed scope

Add a **Locations** (Devices) section to the sidebar that lists mounted
removable/external volumes — SD cards, USB drives, connected cameras exposed as
volumes.

- Enumerate mounted volumes via `FileManager.mountedVolumeURLs` with the
  `.volumeIsRemovableKey` / `.volumeIsEjectableKey` / `.volumeIsInternalKey`
  resource keys; show removable/ejectable (and external) volumes, hide the boot
  volume and system partitions.
- Keep it live: refresh on `NSWorkspace.didMount` / `didUnmount` notifications so
  cards appear on insert and disappear on eject without a relaunch — mirror the
  drive unmount/remount handling already added for persistence (issue 41).
- Clicking a volume navigates the **Active Panel** to its root, consistent with
  Places (reuse `navigateActive(to:)`, issue 15).
- Per-volume eject affordance (hover / context menu) — nice-to-have, can be a
  follow-up.

### Triage decisions (2026-07-05)

- **Scope: mounted volumes only.** SD cards, card readers, USB drives, cameras in
  mass-storage mode. PTP/MTP cameras that expose no `/Volumes` mount are split out
  to **issue 47** (deferred, `needs-triage`).
- **Section name: "Devices".**

## Acceptance criteria

- [ ] A mounted SD card / USB drive appears in a sidebar section within a second
      of being inserted, and disappears on eject — no relaunch needed.
- [ ] Clicking it navigates the active panel to the volume root.
- [ ] The internal boot volume and system partitions are not listed.
- [ ] No card connected → the section is empty/hidden (no dangling chrome).
- [ ] Ejecting from Finder while the panel is showing the card degrades
      gracefully (no crash; matches issue 41 unmount handling).

## Out of scope

- PTP/MTP cameras that don't mount as a volume — see issue 47.
- Network shares, iCloud, remote sources (`PanelSource`, ADR 0003) — future.

## Agent Brief

**Category:** enhancement
**Summary:** Add a "Devices" section to the left sidebar listing mounted removable/external volumes (SD cards, USB drives, card readers, mass-storage cameras), live-updating on mount and eject.

**Current behavior:**
The left sidebar renders only two sections — a fixed "Places" set (Home, Desktop,
Documents, Downloads, Applications) and a user-managed "Pinned" set. Nothing
enumerates mounted volumes and nothing observes mount/unmount events. A connected
SD card or USB drive is reachable only by typing its `/Volumes/...` path into Go
to Folder (issue 15). Locations were explicitly deferred in issue 16.

**Desired behavior:**
A third sidebar section titled **Devices** lists currently-mounted volumes that are
removable or ejectable (i.e. external media), excluding the internal boot volume
and system partitions. The list is live: a volume appears within ~1s of being
mounted and disappears when ejected/unmounted, with no relaunch. Clicking a device
row navigates the **active panel** to that volume's root, exactly like a Places
row. When no external volumes are mounted, the Devices section shows nothing (empty
or hidden) rather than dangling chrome. If a volume is ejected while a panel is
displaying it, the app must degrade gracefully — no crash — consistent with the
existing drive-unmount handling delivered for state persistence (issue 41).

**Key interfaces:**
- Volume enumeration — use `FileManager.mountedVolumeURLs(includingResourceValuesForKeys:options:)`
  and read the `.volumeIsRemovableKey`, `.volumeIsEjectableKey`, `.volumeIsInternalKey`,
  `.volumeNameKey` resource values to decide what to show and how to label it. Show
  volumes that are removable or ejectable (or non-internal); never show the boot
  volume. Prefer `.skipHiddenVolumes`.
- Live updates — observe `NSWorkspace.shared.notificationCenter` for
  `NSWorkspace.didMountNotification` and `didUnmountNotification` (and consider
  `didRenameVolumeNotification`) to refresh the list. There is already
  unmount/remount handling in the workspace/persistence layer (issue 41) — reuse or
  sit alongside it rather than adding a second independent observer if practical.
- Navigation — reuse the existing active-panel navigation entry point that Places
  rows use (the `navigateActive(to:)`-style method on the workspace model from
  issue 15); do not invent a new navigation path.
- Sidebar model/view — the workspace model that owns sidebar state should expose the
  observed device list; the sidebar view renders it as a third section following the
  same row/section styling as Places (icon + name, single click navigates). Match the
  established SF Symbol convention used for Places rows (e.g. `sdcard`/`externaldrive`).

**Acceptance criteria:**
- [ ] With an external volume mounted (a `hdiutil attach` disk image is sufficient
      for testing), a "Devices" section lists it by volume name.
- [ ] Mounting a volume makes its row appear within ~1s without relaunch; ejecting
      it removes the row.
- [ ] Clicking a device row navigates the active panel to the volume root.
- [ ] The internal boot volume and system/hidden partitions are never listed.
- [ ] With no external volumes mounted, no empty "Devices" chrome is left behind.
- [ ] Ejecting a volume while a panel is showing it does not crash (matches issue 41
      unmount behavior).

**Verification without hardware:**
`hdiutil create -size 64m -fs APFS -volname TESTCARD /tmp/testcard.dmg && hdiutil attach /tmp/testcard.dmg`
mounts an ejectable volume that fires the same `NSWorkspace` mount notifications;
`hdiutil detach` exercises the unmount path. Full removable-media testing can use a
real SD card, but the disk-image path covers the mount/unmount/navigate contract.

**Out of scope:**
- PTP/MTP cameras that expose no `/Volumes` mount (ImageCaptureCore / ICDeviceBrowser) — issue 47.
- Per-volume eject affordance in the sidebar — nice-to-have follow-up, not required here.
- Network shares, iCloud, and other `PanelSource` types (ADR 0003).
