# Demand Test — Session Cheat-Sheet (1 page, glanceable live)

> Companion to `demand-test.md`. Print it / keep it beside you. In the session your
> job is to **listen**, not to sell or demo. Every line below in **"quotes"** is meant
> to be said close to verbatim. ~30–40 min.

## Before they arrive
- [ ] App **installed and running** on their Mac (you drove `xattr`/right-click→Open).
      Log any install friction *here*, then set it aside — it is **not** the demand read.
- [ ] Ask to **record** (screen + audio): *"Mind if I record? Only for my own notes."*
- [ ] Have them pick **their own real folder** to work in (Downloads, a project, photos).
      Never your demo files.

## 1 · Frame (say it, then stop)
> **"I built a dual-pane file manager. I want your honest read, not encouragement —
> if it's not for you, telling me *why* is the most useful thing you can do. There are
> no right answers, and you can't hurt my feelings."**

Do **not** explain features. Do **not** say what it's "supposed" to do.

## 2 · The task — hand it over, then go silent
Pick **one** real job (their files). Say it plainly, then **shut up for as long as it
takes** — silence is data:
> **"Using this, can you [organize this messy folder / move these files into that folder /
> rename this series / find that file in there]? Talk out loud as you go if you can."**

**The silence rule:** count to 10 before helping. Only unblock a *hard* stuck (they'd
quit), and note it as friction. Every rescue is a data point you just erased.

### Watch for (jot, don't interrupt)
| Light-up 🔺 | Stall / confusion ⛔ | Reached for a keystroke that isn't there ⌨︎ | Reached back for their OLD tool 🔙 |
|---|---|---|---|

That last column (🔙) is gold: reverting to the old tool mid-task = the switch didn't take.

## 3 · Demand probes (after the task — in order, don't lead)
1. **PMF (Sean Ellis):**
   > **"If you couldn't use this anymore tomorrow — very disappointed, somewhat, or not
   > disappointed?"** … then **"why that?"**
   (Write the *why* verbatim. "Very" is only real if the why is concrete.)
2. **Switching:**
   > **"What would you use this instead of — and honestly, would you actually switch?"**
   (A compliment is not a switch. Listen for inertia: "I'd have to unlearn…")
3. **Referral (make it specific):**
   > **"Who *specifically* needs this — an actual person you'd send it to?"**
   (A named person = pull. "Lots of people would like it" = politeness.)
4. **Values probe:**
   > **"It's native, ~1.5 MB, no telemetry, one-time purchase. Does any of that matter
   > to you — or is it just nice-to-have?"**
   (Per netnography this *should* pull. If it shrugs, note it — positioning risk.)
5. **Pay probe (one-time buy):**
   > **"If this were a one-time €19, would you buy it *today*?"**
   Watch the flinch, not the polite yes. Optional sensitivity:
   > **"At what price would it feel *too cheap to trust* — and too expensive?"**

## 4 · Close — set up the real signal
> **"I'm going to leave it installed and *not* bug you. No pressure to use it."**

- [ ] **Do not nudge afterwards.** The test is whether they open it **unprompted**.
- [ ] Schedule your **~day-10 check** now (calendar it): did they re-open it on their own?
      (Ask, or read it from #48 usage instrumentation if that's live.)

## Hard rules (the ways this test lies to you)
- **Don't demo.** The moment you narrate a feature, the pull signal is contaminated.
- **Don't rescue fast.** Their struggle is the finding.
- **Don't sell.** You're measuring pull, not creating it.
- **Separate usability from demand.** A confusing UI is fixable ≠ "no demand."
- **Friends inflate.** Weight the cold recruits' reads heavier.

## Log immediately after (before you forget)
- Task completed unaided? (y/n) · biggest stall · biggest light-up · reverted to old tool? (y/n)
- PMF bucket + the **why** (verbatim) · would-switch? · named referral? · pay-today?
- One line: **did this person seem to *want* it, or just approve of it?**
